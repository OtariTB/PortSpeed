## Executable dependencies

The main `nfs.exe` has a valid parsed PE32 header, machine `0x14c` (x86), image base `0x400000`, entry RVA `0x428c25`. Sections include `.text`, `.rdata`, `.data`, `.tls`, `.rsrc`, `ars`, `est`, `artem`, `celare`, `.securom`. Names alone do not establish protection behavior or whether code is directly analyzable.

Its static DLL import descriptors name:

- Input/audio/timing: `DINPUT8.dll`, `DSOUND.dll`, `WINMM.dll`.
- C/C++ runtime: `MSVCR80.dll`, `MSVCP80.dll`.
- Windows services: `KERNEL32.dll`, `USER32.dll`, `ADVAPI32.dll`, `SHFOLDER.dll`, `WS2_32.dll`, `RPCRT4.dll`, `ole32.dll`, `NETAPI32.dll`.

No delay-import descriptors were reported for this image. Static names do not prove actual runtime resolution, complete transitive dependencies, or dynamically loaded modules. The parser records DLL names, not imported functions. Local VC80 DLLs report version `8.00.50727.762`; VC71 DLLs are also present. The local `dinput8.dll` reports `1.0.0.0`, so it must not be assumed to be the system DirectInput binary. No installer or library was loaded.

PE interpretation follows [Microsoft's PE specification](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format). Browser adapters for Windows graphics, input, audio, filesystem and timing will eventually be needed; import names do not tell us how much code can be reconstructed or how long a port will take.
